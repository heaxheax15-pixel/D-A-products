TASK 2: ADMIN SECURITY UPGRADES
================================================================================

✅ TASK COMPLETED

Files Modified:
  1. includes/auth.php (Completely Rewritten)
     • Added get_admin_password_hash() function
       - Retrieves bcrypt hash from settings.admin_password_hash
       - Returns null if hash doesn't exist (first login case)
     • Added set_admin_password_hash() function
       - Stores hash in settings table (MySQL & SQLite compatible)
       - Handles both INSERT and UPDATE operations
     • Updated admin_login() function
       - Now accepts plaintext password
       - On first login: compares against ADMIN_SECRET_KEY
       - Hashes ADMIN_SECRET_KEY with PASSWORD_BCRYPT (cost=12)
       - Stores hash for future logins
       - Subsequent logins: uses password_verify() for comparison
       - Timing-safe comparison prevents timing attacks
     • Added check_admin_session_timeout() function
       - Monitors $_SESSION['da_admin_time'] for inactivity
       - 30-minute (1800 seconds) timeout configurable
       - Automatically logs out idle admins
       - Updates timestamp on every request
       - Redirects to login.php with error message
     • Preserved legacy admin_try_legacy_key() for backward compatibility

  2. includes/bootstrap.php (Enhanced)
     • Added enforce_https() function
       - Checks $_SERVER['HTTPS'] for direct HTTPS
       - Checks $_SERVER['HTTP_X_FORWARDED_PROTO'] for proxy HTTPS
       - Detects localhost/127.0.0.1/::1 for development
       - Performs 301 Moved Permanently redirect if not HTTPS
       - Executes BEFORE session_start() for early enforcement
     • Added HSTS header configuration
       - Sets Strict-Transport-Security header for HTTPS connections
       - max-age=31536000 (1 year in seconds)
       - includeSubDomains flag enabled
       - preload flag enabled (browser preload list eligible)
     • Updated session_start() configuration
       - Added cookie_secure flag (set based on HTTPS detection)
       - Maintains cookie_httponly = true
       - Maintains cookie_samesite = 'Lax'
     • Added session timeout check integration
       - Checks current script against admin page list
       - Calls check_admin_session_timeout(30) automatically
       - Applied to: dashboard.php, orders.php, products-management.php, settings.php

Authentication Flow:
  First Admin Login:
    1. User navigates to login.php
    2. Enters ADMIN_SECRET_KEY from .env
    3. admin_login() called with plaintext key
    4. System retrieves admin_password_hash (returns null)
    5. Since null, compares against ADMIN_SECRET_KEY (timing-safe)
    6. If match: hashes ADMIN_SECRET_KEY with password_hash()
    7. Stores hash in settings table: admin_password_hash
    8. Sets $_SESSION['da_admin'] = true
    9. Sets $_SESSION['da_admin_time'] = time()
    10. Redirects to dashboard

  Subsequent Admin Logins:
    1. User enters password
    2. admin_login() called with plaintext
    3. System retrieves hash from settings table
    4. Uses password_verify() to compare (timing-safe)
    5. If match: same session setup as first login
    6. Timestamp updated to current time

  During Active Admin Session:
    1. Page load triggers check_admin_session_timeout()
    2. Calculates time_elapsed = current_time - last_activity_time
    3. If time_elapsed > 1800 seconds (30 minutes):
       - Calls admin_logout()
       - Sets error message in flash session
       - Redirects to login.php
    4. If still active: updates $_SESSION['da_admin_time'] to current_time

Security Benefits:
  ✅ Bcrypt hashing with cost factor 12 (slow brute-force resistant)
  ✅ Timing-safe password comparison (prevents timing attacks)
  ✅ First-login auto-hashing (secure migration from plaintext)
  ✅ 30-minute auto-logout (prevents unauthorized terminal access)
  ✅ HTTPS enforcement (all traffic encrypted)
  ✅ HSTS header (prevents SSL stripping)
  ✅ Secure cookies (HttpOnly + SameSite + Secure)
  ✅ Proxy/load-balancer aware (works with CloudFlare, AWS ELB, etc.)

Transaction Flow (ATOMIC):
  BEGIN TRANSACTION
    ├─ Step 1: LOCK product row (SELECT ... FOR UPDATE)
    ├─ Step 2: Check quantity_available >= requested_quantity
    │  ├─ NO: ROLLBACK (return error, no order created)
    │  └─ YES: Continue
    ├─ Step 3: INSERT INTO orders (...)
    ├─ Step 4: UPDATE products SET quantity_available = quantity_available - requested_qty
    ├─ Step 5: INSERT INTO inventory_transactions (audit trail)
    ├─ Step 6: COMMIT
    └─ Result: ✅ Order confirmed, stock decremented, audit logged

Error Handling:
  • Any exception during transaction: automatic ROLLBACK
  • Partial insertions impossible (all-or-nothing semantics)
  • JSON error responses with HTTP status codes
  • Full error logging for debugging
  • User-friendly messages in Arabic

Security Benefits:
  ✅ ACID Compliance (all database constraints enforced)
  ✅ No double-selling (row-level locking prevents race conditions)
  ✅ Stock integrity (automatic decrement on order confirmation)
  ✅ Audit trail (complete history in inventory_transactions)
  ✅ Atomic operations (no partial orders)
  ✅ Foreign key constraints (referential integrity)
  ✅ Rate limiting (60-second anti-spam protection)

TASK 4: RATE LIMITING (ANTI-SPAM)
================================================================================

✅ TASK COMPLETED (Integrated into submit-order.php)

Implementation Details:
  Location: submit-order.php, Lines 23-34
  Mechanism: Session-based rate limiter (60-second window)
  
  Code Logic:
    if (!empty($_SESSION['last_order_time'])) {
        $timeSinceLastOrder = time() - (int) $_SESSION['last_order_time'];
        if ($timeSinceLastOrder < 60) {
            http_response_code(429);  // Too Many Requests
            return error with countdown
        }
    }
    
    // ... successful order ...
    $_SESSION['last_order_time'] = time();

Features:
  ✅ Per-session rate limiting (independent for each user/session)
  ✅ 60-second mandatory delay between successive orders
  ✅ HTTP 429 status code (standard for rate limiting)
  ✅ Dynamic countdown message (tells user seconds remaining)
  ✅ No database lookups (pure session-based, zero overhead)
  ✅ Zero configuration required (built-in 60-second default)

Example Response (Rate Limited):

  Content-Type: application/json

    "success": false,
    "message": "يرجى الانتظار 45 ثواني قبل تقديم طلب جديد."
  }

Implementation Details:

  Execution: Before session_start() for early enforcement
  
  HTTPS Enforcement Function:
    enforce_https() checks:
      ├─ $_SERVER['HTTPS'] !== 'off' (direct HTTPS)
      ├─ $_SERVER['HTTP_X_FORWARDED_PROTO'] === 'https' (proxy HTTPS)
      └─ If not HTTPS and not localhost: 301 redirect to HTTPS

  Proxy Support:
    • Works with reverse proxies: CloudFlare, AWS ELB, Nginx, Apache
    • Detects X-Forwarded-Proto header from proxy
    • Correctly identifies HTTPS behind load balancer

  HSTS Header Configuration:
    Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
      ├─ max-age=31536000 (1 year = 31,536,000 seconds)
      ├─ includeSubDomains (applies to all subdomains)
      └─ preload (eligible for browser HSTS preload list)

  Localhost Exemption:
    • Development/testing allowed on localhost without HTTPS
    • Skips enforcement for: localhost, 127.0.0.1, ::1
    • Production domains required to use HTTPS

Session Configuration:
  session_start([
      'cookie_httponly' => true,         // No JavaScript access
      'cookie_samesite' => 'Lax',        // CSRF protection
      'cookie_secure' => true_if_https,  // HTTPS only
  ]);

Security Benefits:
  ✅ All traffic encrypted (HTTPS mandatory)
  ✅ 301 redirect prevents man-in-the-middle attacks
  ✅ HSTS prevents SSL stripping attacks (1 year)
  ✅ Browsers enforce HTTPS automatically
  ✅ Works with reverse proxies and load balancers
  ✅ Secure cookies (HttpOnly + SameSite + Secure)
  ✅ Zero configuration required (automatic enforcement)
